

# Pulse Messenger

> **Версия 0.1.90.** Исходник восстановлен из опубликованного OTA-пакета 0.1.89 (ветка `updates`) и снова собирается из этого репозитория. В 0.1.89 по сравнению с 0.1.0 добавлены: новый интерфейс (Фид, Клипы, панель разделов, алфавитная навигация, свайпы), профили с фото, блокировка, непрочитанные, голосовые сообщения и аудиозвонки через сервер на телефоне. Голосовые и звонки пока работают только с сервером на телефоне — Node.js-сервер их не поддерживает.

Прототип Android-мессенджера с интерфейсом в стиле HomePlanner. Локальный режим хранит отдельные заметки на устройстве. Для переписки между устройствами создайте аккаунты на одном сервере Pulse: сообщения сохраняются в очередь и отправляются при восстановлении связи. Синхронизация работает, пока приложение открыто.

## Сервер

Нужен Node.js 20 или новее. Из папки `server`:

```sh
npm test
PORT=3000 PULSE_DATA=/путь/к/закрытой/папке/data.json npm start
```

Это отдельный интернет-сервер на Node.js. Он слушает только `127.0.0.1`. Для доступа с телефонов настройте домен и HTTPS-прокси, который передаёт запросы на `127.0.0.1:3000`. Например, для Caddy, заменив `pulse.example.com` своим доменом:

```caddyfile
pulse.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

DNS и порты для выдачи сертификата должны быть настроены на сервере. В приложении укажите HTTPS-адрес без пути, например `https://pulse.example.com`. Незащищённый HTTP допускается только для локальных адресов разработки `localhost`, `127.0.0.1` и `10.0.2.2`. На Android-эмуляторе `10.0.2.2` обозначает компьютер, на котором работает эмулятор. Для сервера телефона используйте ссылку подключения с HTTPS и отпечатком сертификата, как описано ниже.

## Сервер прямо на телефоне

1. В настройках Pulse нажмите «Запустить сервер». Установка Node.js, Termux и облачная база не нужны.
2. Нажмите «Подключиться на этом телефоне»: адрес заполнится в форме входа. Создайте аккаунт. Если уже выполнен вход на другой сервер, сначала перейдите в локальный режим.
3. Подключите второй телефон к той же сети Wi-Fi. Нажмите «Поделиться подключением» и передайте полную ссылку. При нескольких сетевых интерфейсах выберите адрес своей Wi-Fi-сети.
4. На втором телефоне вставьте ссылку в поле сервера в настройках, создайте другой аккаунт и откройте чат по имени первого пользователя. Оба аккаунта должны находиться на одном сервере.
5. Остановить сервер можно в настройках или уведомлении. Аккаунты, сессии и сообщения сохраняются и доступны после повторного запуска.

Сервер слушает IPv4-порт 8443 на сетевых интерфейсах телефона. Если порт занят, запуск завершится ошибкой. Ссылка имеет вид `https://192.168.1.20:8443#sha256=<64 шестнадцатеричных символа>`. Отпечаток привязывает соединение к сертификату именно этого телефона; другие самоподписанные сертификаты отвергаются. Передавайте ссылку непосредственно владельцу второго устройства. Для обычных интернет-серверов без отпечатка сохраняется стандартная проверка HTTPS. Незашифрованное подключение по Wi-Fi не разрешено.

Закрытый ключ сертификата хранится в AndroidKeyStore. Серверная SQLite-база `pulse-host.db` отделена от клиентской `pulse.db` с заметками и очередью; остановка сервера не стирает ни одну из них. Пароли серверных аккаунтов хранятся как PBKDF2-HMAC-SHA256 (120 000 итераций, случайная соль), сессионные токены — как SHA-256. SQLite-файл не шифруется отдельно, сообщения доступны серверу: сквозного шифрования нет. Аккаунты отдельного Node.js-сервера и телефона независимы, автоматического переноса между ними нет. Не очищайте данные приложения и не удаляйте его, если нужна история: это удалит базу и ключ. Отдельного экспорта серверной базы пока нет.

Пока сервер включён, работает foreground service и удерживается процессор — это расходует заряд. Android может завершить процесс; после перезапуска приложения включите сервер снова. На Android 13+ уведомление отображается, если разрешены уведомления; сервер также доступен через системный список активных приложений. Изоляция клиентов в Wi-Fi или ограничения роутера могут мешать соединению. Если IP телефона изменился, передайте новую ссылку: ключ и аккаунты останутся прежними. Доступ из интернета через NAT автоматически не открывается; для телефона потребуется отдельно настроенный HTTPS-туннель. Для постоянного интернет-сервера используйте Node.js-вариант выше.

В `VailaLauncher3` использована Supabase-таблица профилей с разграничением доступа по владельцу; встроенного сервера на телефоне в доступном исходном коде нет. Здесь тот же принцип изоляции применяется к существующей клиентской базе и серверному API без зависимости от Supabase. `pulse-messenger` на момент проверки возвращал 404.

Запускайте только один процесс сервера для одного файла данных. Файл содержит историю сообщений и данные аккаунтов: храните его в закрытой папке и регулярно делайте резервные копии. Пароли хранятся в виде scrypt-хешей, токены — в виде SHA-256-хешей. Сервер хранит сообщения в открытом виде; сквозного шифрования нет. Не используйте прототип для конфиденциальной переписки. Ограничение попыток входа действует по IP; за обратным прокси общий лимит может применяться ко всем клиентам.

## Android

APK собирает GitHub Actions (`.github/workflows/android.yml`) при каждом пуше в `main`; готовый файл лежит в артефактах запуска. Для локальной сборки нужны JDK 17, Gradle 8.11.1 и Android SDK 35:

```sh
gradle -p android --no-daemon :app:assembleDebug
```

### Ключ подписи

Все сборки подписываются одним ключом `android/signing/pulse-release.jks` (пароль в `.github/workflows/android.yml`), поэтому обновления ставятся поверх. Ключ лежит в публичном репозитории: любой может подписать им свой APK, так что ставь chatPuls только из этого репозитория или через встроенное обновление.

### OTA-обновления

При каждом пуше в `main` с увеличенным `versionCode` workflow сам публикует OTA: APK попадает в `releases/` ветки `updates`, а `latest.json` обновляется.

Версия 0.1.89 подписана старым debug-ключом, поэтому переход на 0.1.90 требует один раз удалить приложение и установить новое вручную. Локальные чаты и база сервера на телефоне при этом удалятся.

Новый чат открывается по имени пользователя из латинских букв, цифр и `_` (3–32 символа). Для интернет-переписки получатель должен зарегистрироваться на том же сервере. Отдельные локальные заметки не отправляются в интернет и не переносятся в аккаунт. При выходе из аккаунта история остаётся на устройстве и доступна после повторного входа на тот же сервер под тем же именем. Уведомлений, вложений и фоновой синхронизации пока нет.

На странице «Чаты» плавающая кнопка «+» открывает новый чат. «Все» показывает чаты вне архива, «Входящие» — чаты, в которых есть полученные сообщения, а «Архивные» — перемещённые в архив. Меню рядом с чатом переносит его в архив или возвращает обратно без удаления истории. 

В «Ленте» под шапкой доступны собственные вкладки «Стена», «Новости», «Сообщества»; выбор сохраняется при переключении разделов и пересоздании экрана. Публикации пока не подключены.

## Обновления приложения

При открытии Pulse проверяет `https://raw.githubusercontent.com/dozyFJ/chatPuls-/updates/latest.json`. Если найдена новая версия, приложение скачивает её, сверяет SHA-256, имя пакета, код версии и подпись с установленной версией и предлагает установить. В настройках можно повторить проверку или открыть установку позже. Для установки Android может попросить разрешение на установку из этого источника и всегда показывает системное подтверждение; после обновления откройте приложение снова. Проверка и скачивание работают, пока процесс приложения запущен; после его завершения проверка повторится при следующем открытии.

Для выпуска создайте приватный ключ подписи и сохраните его в надёжном месте. Первая установленная версия и все последующие обновления должны быть подписаны одним ключом. Для подписанной release-сборки задайте все четыре переменные `PULSE_KEYSTORE` (путь к keystore), `PULSE_STORE_PASSWORD`, `PULSE_KEY_ALIAS`, `PULSE_KEY_PASSWORD` и выполните `gradle -p android :app:assembleRelease`. Не добавляйте ключ и пароли в репозиторий. Если переменные не заданы, release APK не будет подписан; отладочный APK подписан другим ключом и не получит обновления, подписанные вашим release-ключом.

Увеличьте `versionCode` и `versionName` в `android/app/build.gradle.kts`, подпишите APK тем же ключом и опубликуйте его вместе с `latest.json` в отдельной ветке `updates`. Например, для файла `releases/PulseMessenger-0.2.0.apk` манифест должен иметь вид:

```json
{
  "versionCode": 2,
  "versionName": "0.2.0",
  "url": "https://raw.githubusercontent.com/dozyFJ/chatPuls-/updates/releases/PulseMessenger-0.2.0.apk",
  "sha256": "SHA256_ПОДПИСАННОГО_APK"
}
```

Вместо значения `sha256` укажите 64-значный хеш подписанного файла, полученный командой `sha256sum`. Используйте только указанный путь и имя файла; другие адреса и APK с неверным хешем, пакетом, версией или подписью отклоняются. Ветка `updates` и подписанный выпуск ещё должны быть опубликованы, иначе проверка обновлений будет завершаться ошибкой.


## Модерация и chatPuls Admin

`android/admin` — отдельное приложение **chatPuls Admin** (APK лежит в Releases рядом с chatPuls). Оно работает с обоими серверами:

- **Сервер на телефоне:** в chatPuls откройте «Настройки → Сервер на этом телефоне → Ключ администратора» и поделитесь им в chatPuls Admin. Там же ключ можно сменить.
- **Node.js-сервер:** ключ печатается в консоли при первом запуске. Можно задать свой через `PULSE_ADMIN_TOKEN` (64 символа 0–9, a–f).

Возможности: статистика, очередь жалоб (пользователи жалуются из chatPuls долгим нажатием на сообщение или через меню чата), удаление сообщений (они исчезают у обоих собеседников при синхронизации), баны и завершение сеансов.

### Роли

- **Пользователь** — обычный аккаунт.
- **Админ 🛡** — модерирует жалобы, банит обычных пользователей. Входит в chatPuls Admin своим chatId и паролем.
- **Главный админ 👑** — всё то же, плюс назначает и снимает админов и может банить админов.
- **Владелец сервера** (ключ администратора) — может всё, в том числе назначать главных админов.

Чтобы стать главным админом: войдите в chatPuls Admin ключом сервера, откройте «Пользователи», выберите свой chatId → «Сделать главным админом». Потом можно входить аккаунтом.

Admin API: заголовок `X-Pulse-Admin: <ключ>` или `Authorization: Bearer <сеанс>` аккаунта с ролью; `GET /v1/admin/me`, `POST /v1/admin/roles {name, role: user|admin|superadmin}`, `GET /v1/admin/stats`, `GET /v1/admin/users?q=`, `POST /v1/admin/users {name, action: ban|unban|logout}`, `GET /v1/admin/reports[?status=all]`, `POST /v1/admin/reports {id, action: dismiss|delete|ban|delete_ban}`. Пользовательский `POST /v1/reports {to, id?, reason}`.

## Пульс дружбы: подписки и друзья

- **Подписка** односторонняя. **Друзья** — когда подписаны друг на друга. **Близкие 💗** — друзья с пульсом от 60.
- **Пульс дружбы** (0–100) считает сервер по переписке пары за последние 14 дней. Важна взаимность: учитывается меньшая из двух сторон (`25·log2(1 + min(a→b, b→a))`).
- У записей на стене и у историй есть аудитория: все подписчики, только друзья или только близкие.
- Профиль (имя, аватар, фон) отправляется на сервер и виден другим.

API (сессия пользователя): `GET /v1/people?q=`, `GET /v1/friends`, `POST /v1/follow {name, follow}`, `GET|POST /v1/profile`, `POST /v1/posts {text, audience}`, `POST /v1/posts/delete {id}`, `GET /v1/posts?name=`, `GET /v1/feed`, `POST /v1/stories {image, audience}`, `POST /v1/stories/delete`, `GET /v1/stories`, `GET /v1/story?name=`.
