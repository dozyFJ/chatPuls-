# AGENTS.md — инструкция для ИИ-агентов (Codex, Claude и др.)

Прочитай целиком перед любыми изменениями. Здесь собраны правила, нарушение которых ломает установленные у пользователей приложения.

## Что это за проект

**chatPuls** (бывш. Pulse Messenger) — Android-мессенджер на Java без фреймворков: весь UI строится кодом, XML-разметки нет.

- `android/app` — приложение **chatPuls**, пакет `dev.dozyfj.pulsemessenger`.
- `android/admin` — приложение **chatPuls Admin** для модерации, пакет `dev.dozyfj.chatpuls.admin`.
- `server/` — Node.js-сервер (Node 20+, без зависимостей, данные в JSON-файле).
- Второй сервер встроен в само приложение: «сервер на телефоне» (`PhoneServer`, `PhoneServerStore`, SQLite `pulse-host.db`, HTTPS на порту 8443 с самоподписанным сертификатом и пиннингом по `#sha256=…`).

Интерфейс и тексты — **на русском**. Пользователь пишет коротко и с опечатками: уточняй, если смысл неясен.

## Сборка и проверка

- APK собирает GitHub Actions (`.github/workflows/android.yml`) при каждом пуше в `main`: сервер-тесты, `:app` и `:admin` `assembleRelease`, загрузка в GitHub Releases, публикация OTA.
- Локально: JDK 17, Gradle 8.11.1, Android SDK 35 → `gradle -p android --no-daemon :app:assembleRelease :admin:assembleRelease`.
- Тесты сервера: `cd server && npm test` (node --test). **Перед пушем должны проходить.**
- Android unit-тестов сейчас нет (старые удалены). Минимум — проект должен компилироваться.

## Версии и OTA — самое важное

1. При любом изменении `android/app` **увеличь `versionCode` на 1** и поменяй `versionName` в `android/app/build.gradle.kts`. Для админки — то же в `android/admin/build.gradle.kts`. Без роста `versionCode` OTA не публикуется.
2. CI сам кладёт APK в ветку `updates` (`releases/`) и обновляет `latest.json` (chatPuls) и `admin-latest.json` (Admin). **Не редактируй ветку `updates` руками.**
3. Не меняй имена файлов APK: `PulseMessenger-<версия>.apk` и `chatPuls-Admin-<версия>.apk`. На них завязана проверка URL в `UpdateClient` (`APK_URL`).
4. Не меняй `applicationId` и `namespace` — иначе обновления перестанут ставиться поверх.
5. **Ключ подписи** `android/signing/pulse-release.jks` (alias `pulse`, пароль в workflow). Им подписаны все сборки начиная с 0.1.92. Не удаляй и не заменяй его: OTA проверяет, что подпись совпадает с установленной версией. Новый ключ = все пользователи должны удалить приложение и потерять локальные данные.
6. `UpdateClient`/`UpdateManager` в админке — копия из `app` с заменой путей (`admin-latest.json`, `chatPuls-Admin-`). Меняешь логику OTA — синхронизируй обе копии.
7. Не запускай несколько пушей подряд, пока предыдущий workflow не закончился: оба пытаются запушить в `updates`.

## Базы данных

- Клиент: `ChatStore` (`pulse.db`, сейчас `VERSION = 6`). Сервер в телефоне: `PhoneServerStore` (`pulse-host.db`, версия 5).
- Миграции **только добавляющие**: новая версия → новый блок `if (oldVersion < N)` в `onUpgrade`. Никогда не удаляй таблицы и колонки и не меняй старые блоки миграций — у пользователей уже есть данные.
- `ChatStore` — синглтон (`ChatStore.get(context)`), не создавай `new ChatStore`.
- Node-сервер: новые поля в `state` добавляй через `state.x ??= …` в `createServer`, чтобы старые `data.json` продолжали работать.

## Два сервера — один API

Любой эндпоинт должен работать **одинаково** в `server/server.js` и в `PhoneServer` + `PhoneServerStore`. Добавил в одном — добавь в другом и напиши тест в `server/test/server.test.js`.

Основное API (подробнее — в README):
- Аккаунты: `POST /v1/register`, `POST /v1/login` → `{username, token}`; дальше `Authorization: Bearer <token>`. Логин в UI называется **chatId** (`[a-z0-9_]{3,32}`).
- Сообщения: `GET /v1/messages?after=N&removed=M` → `{messages, removed}`, `POST /v1/messages`, `POST /v1/voice` (только телефонный сервер), `/v1/calls` (только телефонный сервер).
- Жалобы: `POST /v1/reports`.
- Соцчасть «Пульс дружбы»: `/v1/people`, `/v1/friends`, `/v1/follow`, `/v1/profile`, `/v1/posts`, `/v1/posts/delete`, `/v1/feed`, `/v1/stories`, `/v1/stories/delete`, `/v1/story`.
- Админка: `/v1/admin/*`, доступ по заголовку `X-Pulse-Admin: <ключ>` (владелец сервера) или по сессии аккаунта с ролью `admin`/`superadmin`.

Правила, которые нельзя ослаблять:
- Роли: `user < admin < superadmin < owner(ключ)`. Действовать можно только над теми, кто ниже. Главных админов назначает только владелец. **Никогда не прописывай конкретный ник (например, dzfx) админом в коде** — его может зарегистрировать кто угодно.
- Забаненный пользователь получает 403 и не может войти. Пароли — PBKDF2/scrypt, токены хранятся как SHA-256. Не логируй и не возвращай пароли и токены.
- Лимиты тела запроса: обычные 16 КБ, `/v1/voice` 100 КБ, `/v1/profile` и `/v1/stories` 600 КБ. Не убирай лимиты.
- Пульс дружбы: `25·log2(1 + min(a→b, b→a))` по сообщениям за 14 дней, максимум 100. Уровни: `following`, `follower`, `friend` (взаимная подписка), `close` (друг с пульсом ≥ 60). Аудитории записей и историй: `all`, `friends`, `close`.

## Устройство клиента (`MainActivity`, ~5300 строк)

- Один `Activity`, экраны переключаются полем `page` + `render()`. `render()` полностью пересобирает `content`.
- Страницы: `0` чаты, `1` контакты, `2` настройки, `4` сообщества, `5` клипы, `6` профиль («Фид»), `7` звонки. Внутри `6`: вкладки `feedSection` — Лента / Альбом / Рекомендации, плюс режимы `openProfile` (чужой профиль) и `friendsOpen`.
- Панель иконок над доком: `FEED_SECTIONS` + `FEED_SECTION_TABS` (раздела «Группы» больше нет — вместо него «Сообщества»).
- Сеть — только в фоне: `this.worker` (один поток) или `serverCall(path, body, onResult, onError)`; результат возвращать через `this.handler`. Никогда не делай сетевые запросы на главном потоке.
- Синхронизация: `sync()` раз в 6 с, перерисовывает список **только если данные изменились** — не возвращай перерисовку каждые 6 секунд (ломает свайпы и прокрутку).
- Оформление: `glass(radius)` (glassmorphism), `card()`, `surface()`, `accentPill()`, тёмная тема через `this.dark`. Фон — `DoodleBackground` (узор из иконок + цветные пятна). Новые карточки делай через `newCard()`/`glass()`, а не сплошным цветом.
- Иконки — векторы в `res/drawable` (`ic_*.xml`). Новый `R.id`/ресурс — не забудь создать в `res/values` (например, `ids.xml`), иначе сборка упадёт.
- Код частично восстановлен декомпиляцией из APK 0.1.89: встречаются имена вида `somethingStepNN` и `jumpToLetter`. Их можно переименовывать, но аккуратно и с компиляцией.

## Ограничения, о которых нужно помнить

- Голосовые и звонки работают только с сервером на телефоне; Node-сервер их не умеет.
- Звонки — WebRTC без STUN/TURN, только в одной сети.
- Стена/альбом/истории без входа на сервер хранятся только на телефоне.
- Модерации записей и историй в админке пока нет (жалобы только на сообщения).
- В Google Play это приложение в текущем виде не пройдёт: встроенное OTA там запрещено, нужна отдельная сборка без него.
